# Salted SHA-256 digests of the operator identity terms this PUBLIC repo must
# never publish: personal names, personal handles, brand domains, an AWS
# account id, a phone number, a cloud budget UUID.
#
# WHY DIGESTS AND NOT THE TERMS
#
# A denylist of personal terms in a public repo IS the leak. That is why the
# cleartext list lives out of the tree (.pii-denylist, $OPS_PII_DENYLIST).
#
# But an out-of-tree file does not exist in CI, so the identity check SKIPped
# there — and a skip is why a personal name reached a public commit message and
# a public PR body while `pii-gate` reported success run after run. Hashing lets
# CI refuse a term it is not allowed to know.
#
# This is obscurity, not secrecy. A 12-digit account id has little entropy and a
# reader with a wordlist can recover it. That is an acceptable trade: the goal is
# to keep this data off a public, search-indexed surface, not to hide it from
# someone who already has it.
#
# ADDING A TERM — never paste the term itself:
#   claude-ops/bin/ops-pii-scan --digest 'the term' >> claude-ops/tests/pii-term-digests.txt
#
# Matching is whole-token (and adjacent-word-pair, for "first last" names), so a
# term cannot fire in the middle of an unrelated identifier.
