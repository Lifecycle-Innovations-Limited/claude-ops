# Public third-party constants this repo is allowed to hardcode.
#
# WHY THIS FILE EXISTS
#
# An identifier denylist can only ever hold the OPERATOR's own terms. It
# structurally cannot hold a third party's identifiers — a client's workspace
# UUIDs, their team keys, their issue ids — because nobody knows them in
# advance. So `test-no-secrets.sh` inverts the rule for identifier-shaped
# literals: every UUID and every issue-tracker-shaped key in the tree FAILS
# unless it is listed here with a reason.
#
# That is the point. Adding an entry is a deliberate, reviewable line in a diff
# that says "this identifier is public and belongs to a vendor". Pasting a
# client's UUID cannot be done quietly any more; it has to be argued for here
# first, in front of a reviewer.
#
# WHAT MAY GO IN
#
# Only identifiers that are published by their owner and identify a VENDOR, not
# a customer: an OAuth client_id from a vendor's own CLI, an operating-system
# GUID from vendor documentation, a spec-defined constant. One entry per line,
# each preceded by a comment naming the vendor and where the value is published.
#
# WHAT MAY NOT
#
# Anything that identifies a person, an organisation you work with, or a
# workspace: Linear/Jira/Asana team ids and keys, issue ids, org ids, account
# ids, tenant ids, project ids, calendar ids, channel ids. Those belong in the
# environment — see docs/LOCAL-PREFS.md. If you are tempted to add one here to
# make the build pass, the build is right and the code is wrong.
#
# FORMAT
#
#   uuid:<value>       a full UUID literal that may appear anywhere in the tree
#   issue-prefix:<KEY> an uppercase prefix that may appear as <KEY>-<number>
